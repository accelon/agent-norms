# 主張層：把散文拆成可驗證的斷言

> 這是 [`corpus-to-mobile-skills.md`](corpus-to-mobile-skills.md) 核心論述裡「主張層」那一行的展開。
> 圖解：`中醫知識庫-主張層-01-一句話的解剖.jpg`（上）、`中醫知識庫-主張層-02-主張怎麼活.jpg`（下）。
> 原文：`主張層-01-一句話的解剖.html`、`主張層-02-主張怎麼活.html`（依賴同層 `series.css`、`claim.css`）。

## 1. 一句話

主張層只做一件事：把「一段話」變成「一句一句可以被指到、被推翻、被替換的斷言」。

它只有兩條禁令，其餘的欄位、類型、狀態、版本，都是為了讓這兩條可以被執行：

1. **一條主張不能沒有出處。**
2. **一段散文不能算一條事實。**

記住這兩句，就不會把這一層做成一堆好看的表格。

## 2. 為什麼要這一層

三層各回答一個問題，缺中間那層，上下兩層就得互相污染：

| 層 | 回答 | 產物 | 壞掉的樣子 |
|---|---|---|---|
| 證據層 | 這句話在哪 | 卷／篇／行、版本、頁碼、內容指紋 | 原文被改寫、版本混在一起 |
| 主張層 | 這句話主張什麼 | 主體・屬性・值・條件 ＋ 引用・狀態・版本 | 沒有出處的漂亮話 |
| 閱讀層 | 讀者怎麼讀到 | 30–120 字條目、行內展開、圖譜 | 把建庫過程倒給讀者 |

**散文有四個不可**，所以它不能直接當知識庫的內容：

- **不可比對**：換一個版本，只能重讀，沒辦法 diff。
- **不可計數**：不知道一部書裡有幾條事實，就估不出工、也驗不了收。
- **不可局部修**：改一個劑量要重寫整段，而且看不出改了哪裡。
- **不可組合**：同一條事實沒辦法同時供網頁、書稿、教材、圖譜用不同說法。

主張層的價值就是一句話：**把「可讀」和「可查」分開**。閱讀層服務讀者，主張層服務檢查。

打個比方（借編譯器的做法）：原文是原始碼，主張是中間表示，條目是目標碼。中間表示可以被檢查，錯誤就停在這一層，不會漏到讀者眼前；換一個目標（網頁、書稿、教材）也不必重跑前端。這正是「下層不改，上層可重做」。

## 3. 一條主張的十格

一條主張要回答三組問題。少一格，就退回散文，或退回意見。

| 組 | 格 | 回答什麼 | 缺了會怎樣 |
|---|---|---|---|
| **斷言** | 主體 | 講的是誰 | 不知道在講哪個方、哪味藥 |
| | 屬性 | 講它的哪一面 | 不知道是組成、劑量還是禁忌 |
| | 值 | 講成什麼 | 沒有內容 |
| | 條件 | 在什麼條件下才算 | 把「溫服一升」讀成「一升」 |
| **憑據** | 引用 | 憑哪一段原文 | 讀者回看不到，變成另一種權威 |
| | 逐字 | 引文對上的比例 | 分不清原文與改寫 |
| | 指紋 | 引用有沒有被動過 | 版本一換，引用靜默失效 |
| **治理** | 狀態 | 現在算不算數 | 草稿與定稿混在一起 |
| | 版本 | 這是第幾版 | 改了不知道改了什麼，也回不去 |
| | 簽核 | 誰負責 | 高風險條目沒人敢背書 |

前四格是「話」，後六格是「憑據與治理」。**沒有後六格，前四格只是意見**——而意見不該長得像知識。

## 4. 顆粒度四原則

1. **一主張一斷言**：能被單獨推翻。推翻不了、也證實不了的，不是主張。
2. **一個主體**：不要把「桂枝湯與麻黃湯」寫成一條。
3. **一組引用**：可以跨條文（例如禁忌跨 §12 與 §16），但必須是同一個版本。
4. **不跨版本**：版本是主張的維度，不是主張的內容。兩個版本的說法要拆成兩條，並存。

反例：「桂枝湯治太陽中風，桂枝三兩，禁生冷。」——三件事塞一條。錯了不知道錯哪，改了不知道改哪，審核的人也只能整段重看。

## 5. 類型決定驗證

類型不是分類學，是**規則的開關**。同一句話換一個類型，機器查的東西、簽核的人都不一樣。

（playbook 寫「3–6 類」；中醫這裡把「煎服」拆成用法與劑量兩類，所以是 7 類——合併回 6 類也說得通，重點是每一類都要有自己的檢查動作。）

例：「三兩」在「組成」裡是文字（要對齊藥名與炮製字），在「劑量」裡是數值（要換算、要上限）。

| 類型 | 它回答什麼 | 機器先查什麼 | 簽核 |
|---|---|---|---|
| 組成 | 這個方由什麼構成 | 藥名對齊、炮製字、劑量單位 | 專家 |
| 主治 | 治什麼證 | 證名對齊、條文逐字比對 | 專家 |
| 藥性 | 性味、歸經、功效 | 本草條目比對、異體字 | 專家 |
| 劑量 | 用多少 | 古今單位換算、上限檢查 | **雙簽** |
| 炮製 | 怎麼處理 | 術語表、去皮／炙／擘 | 專家 |
| 用法 | 怎麼煎、怎麼服 | 水量、火候、服次 | 專家 |
| 禁忌 | 什麼情況不能用 | 規則庫、交互與人群檢查 | **雙簽** |

劑量與禁忌的錯，不是「讀起來怪」，是「會傷人」——風險不對稱的類型，一律雙簽。

## 6. 狀態與四道閘門

```text
草稿 ──①── 有引用 ──②── 已驗證 ──③── 已審核 ──④── 已發布
```

| 閘門 | 規則 |
|---|---|
| ① 草稿 → 有引用 | 無引用，不成立 |
| ② → 已驗證 | 引文逐字未達 100%，標 paraphrase 或退回；不准靜默改字 |
| ③ → 已審核 | 劑量、禁忌等高風險，雙簽才算過 |
| ④ → 已發布 | 發布後只增不改；要改，出新版 |

發布之後只有三種結局：**修訂**（v+1，舊版留著，可回滾）、**作廢**（標記，不刪除）、**存疑**（兩種說法並存，各帶來源）。

機器只做能逐字證明的事（對齊、比對、換算、規則檢查）；人只做判斷（對不對、要不要、能不能）。這條分工線畫在「已驗證 → 已審核」之間，不畫在更前面。

## 7. 三種關係

主張不是孤島。它和別的主張之間只有三種關係：

- **依賴**：桂枝湯・組成 → 桂枝・藥性。被依賴的那條改了，依賴它的全部重驗（不是重寫，是重跑）。
- **衝突**：§12 說「三兩」，別本說「二兩」。**不取平均、不折衷**；兩條並存、各帶版本。
- **組合**：四條主張 →（編譯）→ 一個條目。缺一條，條目缺一角。

為什麼衝突不取平均？因為知識庫不是民調。兩個版本各帶出處，讀者要能看到「分歧本身」；把分歧壓成一個數字，等於替讀者做了他沒授權的判斷。

## 8. 六個反模式（圖上只列最常見的四個）

1. **一段散文＝一條事實**：錯了只能整段重寫，也數不出到底幾條。
2. **沒有出處的漂亮話**：讀者回看不到原文，它就變成另一種權威。
3. **把解釋當主張**：解釋會過時，原文不會；解釋要明標「推論」，不能混進引用。
4. **把版本差異壓成一句**：讀者以為只有一種說法，其實是兩種。
5. **一條主張塞多個斷言**：審核無法局部通過，也無法局部推翻。
6. **用「據說」「一般認為」當引用**：那不是憑據，是修辭。

## 9. 量與成本：接到 token 模型

`TCM-TOKEN-MODEL.md` 的假設是「一條 = 1 個概念 = 30–120 字定義 ＋ 3–8 條主張 ＋ 引用」。所以：

- **10,000 條目 ≈ 3–8 萬條主張**。這是真正的生產與審核單位。
- 每條 135k 算力裡，校對佔 66k（3 次、60k in / 6k out）——校對做的主要就是「逐條對引文」，也就是主張層的工作。算力花最多的地方，正是省專家時間的地方。
- 驗收指標全部落在主張上：引用逐字命中率 ≥95%、每條審核 ≤30 分鐘、每條 ≤150k。條目只是彙總後的說法。
- 主張可加、可分工、可抽樣：試點 1,000 條目就是 3,000–8,000 條主張，抽 200 條做審核一致性檢查，就能估出生產線的良率。

## 10. 驗收清單

- [ ] 每條主張：1 組引用、1 個狀態、1 個版本、1 個簽核人
- [ ] 引用逐字命中率 ≥95%，其餘明確標 paraphrase
- [ ] 每個條目 3–8 條主張；超出就拆條目，不是硬塞
- [ ] 劑量、禁忌雙簽；其餘單簽
- [ ] 任一主張可回滾；改一條，不必動原文
- [ ] 抽 20 條主張，兩個審核者獨立判斷，結論一致率 ≥90%

## 11. 換領域：類型怎麼填

類型不是越多越好，3–7 類；每一類都要能對上一種「機器可查的東西」，否則那一類只是標籤。

| 領域 | 主張類型 | 高風險（雙簽） |
|---|---|---|
| 中醫 | 組成／主治／藥性／劑量／炮製／用法／禁忌 | 劑量、毒性、配伍、妊娠 |
| 法律 | 構成要件／效果／程序／期限 | 時效、管轄、罰則 |
| 工程 | 材料／規格／公差／測試 | 安全係數、承重、電氣 |
| 農業 | 品種／播期／水肥／病蟲 | 農藥劑量、安全間隔 |
| 飲食 | 成分／劑量／人群／禁忌 | 過敏原、孕婦、兒童 |

## 12. 三句話

1. 主張層不是把話說得漂亮，是讓每一句話都能被指到、被推翻、被替換。
2. 沒有引用，不成立；一段散文，也不算一條事實。
3. 所以一個條目可以重編，一條主張可以重審，而原文不必重打。
